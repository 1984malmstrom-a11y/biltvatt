# Arena accounts and station boundaries

This foundation is implemented and verified locally. No Cloudflare resources or remote databases have been changed.

Integrated stations continue to use their existing `STATION_ID` and `DB` binding. Bootstrap synchronizes that station's existing staff register. For an integrated station accessed from a shared Arena host, configure the corresponding server-controlled `STATION_DB_TINGSRYD`, `STATION_DB_KARLSHAMN` or `STATION_DB_KARLSKRONA` D1 binding. Missing bindings fail closed; the host's staff database is never used for a different station. No such live bindings have been configured by this work.

An Arena-only host uses `ARENA_ONLY=1` and `ARENA_DB`. Arena routes do not require a station dashboard database. Use `/arena` as the entry link. The worker also supports redirecting `/` to `/arena`; an Arena-only deployment must include `/` in its assets `run_worker_first` routing to invoke that redirect. Existing integrated asset routing has not been changed. Dashboard APIs are unavailable in Arena-only mode. New signup stations receive `kind=arena`, a generated identity and `status=pending`. Pending stations can view their own account but cannot read Arena results or register sales. Superadmin approval is required. Arena-only station accounts can administer their own sellers and products. Integrated station sellers remain managed by the station dashboard.

Passwords use Workers Web Crypto PBKDF2 with SHA-256, 100,000 iterations, a random 32-byte salt and a 256-bit derived key. The iteration count is stored per account so the KDF can be upgraded later. The current count works with Workers' PBKDF2 iteration limit. Passwords are 12–256 characters and are never stored in plaintext. Login uses a constant comparison of fixed-length hashes and also performs a KDF for nonexistent accounts. Login has an IP limit of 20 attempts/15 minutes and an account limit of 10/15 minutes. Signup is limited to 5 attempts/IP/hour. Limits are persisted atomically in Arena D1.

Station sessions use random 256-bit tokens; only SHA-256 token hashes are stored. Cookies are HttpOnly, SameSite=Lax, Path=/api and Secure on HTTPS. Sessions last 365 days and renew to 365 days when used within the final 30 days. No eight-hour station session or daily logout is introduced. Station accounts can revoke their own sessions. Superadmin can revoke a station's sessions; suspension revokes them immediately. An invalid station cookie never falls back to the integrated host identity.

Superadmin uses a separate `ARENA_SUPERADMIN_SECRET` environment secret of at least 32 characters, separate session storage and a separate cookie with a 12-hour lifetime. Station credentials, station sessions and legacy dashboard admin sessions do not grant Superadmin. No production secret is hardcoded, supplied or configured by this work. Local demo passwords are random and written to a private local credentials file outside Git.

All mutations retain the worker's JSON content-type, size, field allowlist, same-origin and Sec-Fetch-Site protections. Every station-owned query binds the station identity resolved on the server. A client-provided `station_id` cannot select another station. Group result access requires membership. Shared groups expose station totals only, not other stations' individual seller records. Pending and suspended stations are excluded. Total points, integer TB öre and registration counts are marked as totals without normalization. Active seller counts can support a future documented normalization; no working-hour data is invented.

`scripts/seed-arena-network-local.mjs` creates test/demo stations for Tingsryd, Karlshamn, Karlskrona and Arena-only Malmö. It requires the mastertest config and always invokes Wrangler with a fixed `--local` flag. It supports only a local `--persist-to` path, never remote overrides. Existing production station rows and bindings are not seed targets.

Before deployment, review migrations, auth/rate limits, cookie scope for the intended hosts, approval policy and actual integrated D1 bindings. Password recovery, email verification and an external Superadmin identity provider are separate future work; none is simulated by this implementation.
